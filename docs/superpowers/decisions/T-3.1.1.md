# T-3.1.1 — Markdown rendering & sanitization

Status: **awaiting owner** (loop 1, 2026-11-27). Records what `main` already ships; approve with `APPROVED: A`.

## Options

**A. First-party subset parser to React elements (as built). Recommended.** `apps/web/src/lib/prompts/markdown.ts`
parses; `markdown-render.ts` builds elements with `createElement`; never `innerHTML`, so raw HTML is always text.
- Allowed: headings (rendered one level down, the page owns `h1`), paragraphs, lists, fenced code, strong, emphasis,
  inline code, links (`http`, `https`, `mailto` only). Everything else passes through as text.
- Rendering: `markdown-preview.tsx` is a client component, server-rendered on first paint; the editor re-renders live
  on the client. Linear-time scanning, nesting depth cap 8. A render failure shows an inline alert via an error
  boundary.
- Dropped from the dashboard design plan: lazy-loading the renderer (it is small and first-party) and XML-block
  highlighting.

**B. Third-party Markdown library + sanitizer.** Broader syntax, but AGENTS.md forbids new runtime dependencies
without approval, and sanitizing generated HTML is a larger attack surface than never producing HTML.

## Consequences

- With A approved, T-3.1.1 and T-3.1.2 can be ticked. The verifier suggests one more unit test that forces a render
  failure and asserts the inline alert (T-3.1.2 checkbox 2 has no test).
