- apps/web = Next.js 16 App Router + React 19 (Turbopack build), Tailwind 4, Radix/shadcn UI, Supabase cookie auth. Vercel free tier: HTML is Cache-Control no-store (cookie-personalized); only /_next/static is publicly cacheable; device-variant HTML CDN caching must not be attempted on this plan.
- Device split: desktop tree is the src/app/(desktop) route group (public URLs); mobile tree is the real src/app/m segment (internal /m/*). src/proxy.ts selects the tree with NextResponse.rewrite, so the browser URL stays the public path for both devices and RSC navigations.
- Classification order in the proxy: sec-ch-ua-mobile client hint, then classifyDevice() UA regex in src/lib/device.ts. iPads and Android tablets are desktop by policy; each tree stays fluid with Tailwind breakpoints, viewport changes never swap trees mid-session.
- MOBILE_SPLIT_ROUTES in src/lib/device.ts is the contract of split routes; the proxy only rewrites registered paths, so device-neutral pages (sign-in, sign-up, not-found) serve both devices from the shared tree.
- Adding a page with device-specific UI: create app/(desktop)/<route>/page.tsx AND app/m/<route>/page.tsx, add the route to MOBILE_SPLIT_ROUTES, wrap content in components/{desktop,mobile}/app-page.tsx (auth + shell), keep page content in components/shared/*-view.tsx so both trees compose it.
- Bundle isolation comes from per-route module graphs, not conditional rendering: components/desktop/** must never be imported by mobile-tree files or shared code, and vice versa. tests/device-architecture.test.ts enforces the import boundaries and the registry/tree consistency; the e2e "device split" journey verifies chunk divergence, JS bytes and hydration at runtime.
- Hydration is mismatch-free by construction because the device decision lives in routing: SSR and client render the same tree from the same flight payload. Never select trees from window/matchMedia during render; hooks/use-mobile.ts is for leaf-level adaptation inside a tree only.
- Per-page auth stays in AppPage (components/{desktop,mobile}/app-page.tsx) via requireSignedInUser(path), not in layouts, so sign-in return-to deep links keep working (covered by e2e assertions).
