# Web prompts domain

- Schema (supabase/migrations init): prompt text = body of latest `prompt_version` (max version_number). Create inserts prompt + version 1; updates/auto-save overwrite latest version body in place (no history per save). Always also update `prompt` row so `updated_at` trigger fires.
- No DB transactions/RPC: create compensates failed version insert by deleting the prompt row. Agents must not apply DDL to hosted Supabase; new migrations need user approval.
- "Pack" in product language = `category` (one per prompt, composite FK (category_id,user_id) blocks foreign categories -> 23503 -> 422 fields.categoryId).
- Ownership = RLS via user JWT client (`createUserClient` in lib/server/supabase.ts). Foreign or missing or non-UUID id -> identical 404 `PROMPT_NOT_FOUND` body; never 403, never forward PostgREST messages.
- Shared contract (Prompt, PromptListPage, limits, ApiErrorBody, countCharacters = code points to match Postgres char_length) in packages/shared.
- API: /api/prompts (GET list ?q&category&tag&page&pageSize, POST create 201+Location), /api/prompts/[id] (GET, PATCH partial -> saved Prompt, DELETE 204). Route handlers authenticate first (bearer or cookie). proxy ALLOWED_METHODS must include PATCH/DELETE for extension CORS.
- List: order created_at desc, id desc. No q/tag -> range + count exact; out-of-range page raises PGRST103 -> head count, empty items. q/tag -> id-only candidate queries (title `regexIMatch` on prompt, body `regexIMatch` on `prompt_latest_version` view, tag via prompt_tag!inner) merged by `selectMatchingIds`, then fetch page rows. Search uses imatch with `escapeRegexPattern`, not ilike: PostgREST rewrites `*` to `%` in like patterns, so ilike can't match a literal `*`. q/tag are NUL-stripped (`normalizeSearchQuery`); Postgres text rejects NUL.
- PATCH order: prompt row first (title/category, FK check -> 422) then version body, so a rejected update writes nothing; only changed row fields are sent (no stale title write-back), else `updated_at` is touched.
- Module boundary for node tests: anything reachable from route handlers uses `.ts` specifiers, no next/headers, no .tsx. Cookie/notFound page helpers live in lib/server/prompt-pages.ts only.
- Markdown: first-party subset parser lib/prompts/markdown.ts -> React elements via createElement in markdown-render.ts; never innerHTML, so raw HTML is text by construction. Links only http/https/mailto. Linear-time scanning (memoized indexOf finder) and nesting depth cap 8. Markdown headings render one level down (# -> h2) because the page owns the only h1. Card excerpts use `linksAsText` (nested <a> breaks hydration) and `headingsAsText` (bold paragraphs, so excerpts never outrank the card title).
- Auto-save: pure state machine lib/prompts/auto-save.ts (debounce, single-flight with one queued follow-up, retry, flush with keepalive, stop silences). Save closure binds prompt id, which prevents late saves landing in another prompt. prompt-client.ts drops keepalive above 60000 body bytes and wraps fetch (unbound window.fetch throws Illegal invocation).
- Unbounded id reads (search/tag candidates, tag counts) go through `selectAllRows` (range batches until an empty batch) so PostgREST max-rows never truncates silently; every batched query needs a deterministic order.
- Pages: /prompts/[id], /edit, /delete call requireSignedInUser then loadPromptOrNotFound in page.tsx before JSX so notFound() yields a real 404 (no loading.tsx under prompts, or the status degrades to 200). Never import constants from "use client" modules into server components (they become client references); shared UI constants live in .ts modules (e.g. MARKDOWN_PROSE_CLASS in markdown-render.ts).
- Editor leave guard: App Router has no navigation guard, so PromptEditor uses beforeunload + window capture-phase click interception on same-origin links (confirm once per attempt) and flushes on unmount/pagehide; browser back/forward relies on the keepalive flush.
